# Training Note — Годовой план тренировок

Персональный годовой план силовых тренировок и трекер набора мышечной массы с разборной штангой 20 кг (и гантелями 2×10 кг) в минималистичной эстетике Secret Documents / Death Note.

Сайт полностью автономный и статический (чистый HTML5, CSS3, JavaScript ES6+), работает без бэкенда и баз данных:
- Все данные тренировок, история веса и состояние сохраняются в `localStorage` браузера.
- Фотографии тела хранятся локально в браузере через `IndexedDB`.
- Все 20 анатомических изображений упражнений и шрифт `DeathNote` сохранены внутри проекта в папке `assets/`.
- Поддерживает безопасные зоны iPhone (PWA/Safari standalone) и блокирует доступ с Android.

## Публикация на GitHub Pages через GitHub Actions

Сайт настроен для автоматической сборки и публикации по ссылке вида:  
`https://<ВАШ_ЛОГИН>.github.io/<РЕПОЗИТОРИЙ>/`

### Шаг 1. Создайте репозиторий на GitHub
1. Перейдите на [github.com/new](https://github.com/new).
2. Укажите название репозитория (например, `training-note`).
3. Сделайте репозиторий **Public** (публичным).
4. Нажмите **Create repository**.

### Шаг 2. Загрузите файлы проекта
Вы можете загрузить проект через терминал:
```bash
git init
git add .
git commit -m "Initial commit for GitHub Pages"
git branch -M main
git remote add origin https://github.com/<ВАШ_ЛОГИН>/<РЕПОЗИТОРИЙ>.git
git push -u origin main
```
Или загрузите файлы через веб-интерфейс GitHub (**Add file → Upload files**), выбрав все файлы и папки проекта.

### Шаг 3. Включите GitHub Actions для Pages
1. В вашем репозитории на GitHub перейдите в **Settings** (вкладка «Настройки» сверху).
2. В левом меню откройте раздел **Pages**.
3. В блоке **Build and deployment** найдите выпадающий список **Source**.
4. Переключите его с *Deploy from a branch* на **GitHub Actions**.

### Шаг 4. Где смотреть ссылку на готовый сайт
1. Перейдите во вкладку **Actions** в верхнем меню репозитория.
2. Вы увидите запущенный workflow **Deploy to GitHub Pages**.
3. Дождитесь завершения сборки (около 30–60 секунд, появится зелёная галочка).
4. Нажмите на завершённый workflow — в блоке **deploy** появится ссылка на опубликованный сайт:
   `https://<ВАШ_ЛОГИН>.github.io/<РЕПОЗИТОРИЙ>/`
5. Эта же ссылка всегда будет отображаться в **Settings → Pages**.

### Как обновлять сайт в будущем
Любой `git push` в ветку `main` автоматически запустит workflow, пересоберёт сайт и обновит публикацию на GitHub Pages. Также можно запустить сборку вручную во вкладке **Actions → Deploy to GitHub Pages → Run workflow**.

## Секреты и безопасность (API-ключи)

- В репозитории и клиентском коде **нет секретов, токенов или приватных API-ключей**.
- Все 20 иллюстраций упражнений сгенерированы и сохранены локально в папке `assets/images/`.
- Шрифт `DEATHNOTE` лежит локально в папке `assets/fonts/deathnote.otf`.
- Все пути в проекте строго **относительные** (`./assets/...`), поэтому сайт корректно открывается в любой подпапке GitHub Pages без битых ссылок.
- Никакой внешний платный API для работы не требуется.

## Локальная разработка и тестирование

Если хотите запустить или протестировать проект на компьютере:

```bash
# Установка зависимостей
npm install --legacy-peer-deps

# Запуск локального сервера разработки (порт 3000)
npm run dev

# Сборка статики в папку dist
npm run build

# Предпросмотр собранной версии
npm run preview
```
Либо можно просто открыть файл `index.html` прямо в любом современном браузере.
